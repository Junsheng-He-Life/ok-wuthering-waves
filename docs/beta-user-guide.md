# OK-WW macOS 0.1.0-beta.1 使用教程

这是基于 [OK-WW](https://github.com/ok-oldking/ok-wuthering-waves) 的非官方 macOS 源码内测版，使用配套 [OK-Script macOS](https://github.com/Junsheng-He-Life/ok-script) 框架。安装后使用独立面板，不需要安装或保持 Codex 打开。当前面向有人看护的短轮次测试，尚未完成多机器实机验收。

[返回项目首页](../README.md) · [下载本版本](https://github.com/Junsheng-He-Life/ok-wuthering-waves/releases/tag/v0.1.0-beta.1) · [提交问题](https://github.com/Junsheng-He-Life/ok-wuthering-waves/issues)

## 1. 准备运行环境

| 条件 | 要求 |
| --- | --- |
| 电脑 | Apple Silicon Mac，芯片为 M 系列 |
| 系统 | macOS 14 或更新版本 |
| Python | **3.13**，不是 3.12 或 3.14 |
| 编译工具 | Xcode Command Line Tools，包含 `swiftc` |
| 游戏 | 原生《鸣潮》客户端，简体中文界面，默认键位 |
| 显示 | 面板至少需要 920 × 600 逻辑像素的窗口空间，另留出系统标题栏；游戏采集最低 1280 × 720 |

macOS 14 是锁定依赖的安装下限，不表示该版本及所有更新版本均已实机验收。本轮独立环境安装验证在 macOS 26.5.2 的一台 Mac 上完成。本包带安装脚本，但不是自带 Python、已签名或公证的 `.app`。

### 安装 Python 3.13

打开 [Python 官方 macOS 下载页](https://www.python.org/downloads/macos/)，选择 **Python 3.13** 的 macOS 安装器，按提示安装。已安装 Homebrew 的用户也可以在“终端”运行：

```sh
brew install python@3.13
```

重新打开终端，检查版本：

```sh
python3.13 --version
```

应显示 `Python 3.13.x`。安装器也会查找 Python 官方安装目录及 Homebrew 常见目录；不要通过改名其他 Python 版本来跳过检查。

### 安装 Command Line Tools

打开“终端”，执行并完成系统弹出的安装：

```sh
xcode-select --install
```

如果系统提示已经安装，继续检查：

```sh
xcrun --find swiftc
```

返回编译器路径即可。安装过程中不需要启动游戏。

## 2. 下载、安装与启动

1. 打开 [v0.1.0-beta.1 发布页](https://github.com/Junsheng-He-Life/ok-wuthering-waves/releases/tag/v0.1.0-beta.1)。
2. 下载附件 **`ok-ww-macos-beta-0.1.0-beta.1.zip`**，不要用页面自动生成的 `Source code` 压缩包代替。
3. 完整解压到一个准备长期保留的目录。不要单独拖出启动文件，也不要拆开两个项目目录。
4. 双击包根目录的 **`安装与检查.command`**。首次安装会下载固定版本依赖，下载量明显大于源码包；等待出现“安装完成”。
5. 双击同一目录的 **`启动.command`** 打开面板。

解压后的主要文件如下：

```text
解压目录/
├── 安装与检查.command
├── 启动.command
├── 环境诊断.command
├── 先读我.txt
├── release-manifest.json
├── ok-wuthering-waves/
└── ok-script/
```

安装器核对发布文件，创建专用 Python 环境、安装锁定依赖并做离线检查；它不会启动游戏、领取奖励或复制账号配置。再次运行安装器不会重置消费记录。已有环境版本不匹配时，它会报错而不会覆盖。

如果双击 `.command` 无法执行，可以打开终端，输入 `cd `，将完整解压文件夹拖入终端后按回车，然后依次运行：

```sh
bash "安装与检查.command"
bash "启动.command"
```

以后通常只需双击 `启动.command`。排查安装问题时可单独运行：

```sh
bash "环境诊断.command"
```

环境诊断只检查本地运行条件，不连接游戏、采集画面或发送输入。

## 3. 首次设置：权限与独立资源记录

打开面板的 **“首次设置”**：

1. 点击 **“检查运行环境”**，先处理明确列出的缺失项。
2. 点击 **“检查并申请系统权限”**，按系统提示授权。
3. 在 macOS“系统设置 → 隐私与安全性”中，为实际启动程序的终端允许 **屏幕录制** 和 **辅助功能**。屏幕录制可能显示为“屏幕与系统音频录制”。
4. 如果授权后仍无法采集或输入，完全退出启动终端，再重新打开 `启动.command`；仅关闭一个终端标签页可能不够。
5. 真正第一次使用、没有需要恢复的旧记录时，勾选 **“这是第一次在此安装中使用，我没有需要恢复的旧消费记录”**，点击 **“建立本机资源记录”**。

初始化建立本安装的零计数账本和安装标记，补给默认额度为 0。它不会读取或继承发布者的消费额度。检测到旧历史、损坏或丢失的旧账本、初始化中断、待核对消费时，不允许用首次设置清零；按“异常与恢复”的提示处理。

当前不会自动识别游戏账号切换。不同账号应使用各自独立的完整解压目录和资源记录；不同安装之间不自动同步额度。已有账号重新安装或升级时，先阅读本教程的“升级与保留记录”，不要把换目录当作重新计数。

## 4. 游戏准备与第一轮刷取

先进入大世界，手动切换到准备使用的三人队伍，恢复生命值，并确认游戏语言为简体中文。保持以下默认键位：

| 操作 | 按键 |
| --- | --- |
| 战技 / 共鸣解放 / 声骸 | E / R / Q |
| 闪避 | Shift |
| 索拉指南 / 背包 | F2 / B |

面板不会自动修改游戏键位。执行任务时游戏应位于前台，不要最小化。一次只运行一个控制器，避免同时开启旧面板、命令行任务或其他输入工具。

### 读取目标并检查队伍

1. 在 **“开始刷取”** 选择 **“无音区声骸”**、**“Boss 声骸”** 或 **“培养材料”**。
2. 无音区和 Boss 点击 **“读取关卡”**，从当前账号实际列表中选目标。培养材料点击 **“扫描材料需求”**，重新读取当前三人的培养目标和材料需求。
3. 点击 **“检查当前队伍”**。程序读取三人身份、等级、生命值及索拉等级；此步骤会操作菜单和切人，但不进入挑战或领取奖励。
4. 检查显示的三人是否正确。换队或调整槽位后再次检查；角色等级不代表培养材料已经齐全。

### 设置本轮额度

| 控件 | 含义 |
| --- | --- |
| 打完领取奖励 | 勾选时允许在本轮额度内领取波片奖励 |
| 最多消耗波片 | 本轮波片消费上限，最多 360 |
| 最多领取份数 | 本轮奖励份数上限，最多 6；双倍领取计 2 份 |
| 波片不足时，允许在额度内补充 | 显式启用补给；每次打开面板默认关闭 |
| 结晶溶剂 / 个 | 本轮允许使用的溶剂个数，默认 0，最多 6 |
| 储备波片 | 本轮允许提取的储备波片，默认 0，最多 240 |

达到波片额度、份数或其他停止条件中的任意一项，就结束本轮。补给额度只是允许使用的上限，不保证一定使用；补充波片也不会提高本轮消费上限。

第一次无音区试跑可设置 **60 波片、1 份奖励、不补给**。先确认一轮流程和记录，再逐步增加额度。120 波片、2 份可能在一次双倍领取后就结束，并不等于打两场。

声骸任务取消 **“打完领取奖励”** 后进入只吸收模式：波片消费和补给额度强制为 0，份数上限作为战斗场数上限。培养材料任务需要领取奖励。

点击 **“开始刷取”** 后，程序还会重新现场核对队伍，再执行导航、战斗、领奖和恢复流程。单轮运行上限为 10 分钟，暂停时间不计入；本面板不提供无限续跑。

## 5. 队伍与任务支持范围

优先内测组合为 **索拉 8 阶、玄幽东岳无音区、秧秧·玄翎／弗洛洛／穗穗**。三人的角色槽位可以调整，每次开始都会重新识别。

本版本要求三人 **等级至少 80、生命值至少 85%**，且身份和索拉等级明确。80 级只是内测版的保守门槛，不是游戏的通用战力标准。武器、声骸质量和技能练度尚未自动核对，通过基础检查不保证通关。

其他队伍、世界等级或关卡组合，需要勾选 **“允许尝试尚未验证的任务组合”**。此选项不绕过等级、生命值、身份、未支持的 Boss 策略或消费保护。爱弥斯／达妮娅／千咲曾通关但出现减员，仍属于实验性组合。低于门槛时先培养或更换队伍。

## 6. 暂停、继续与结束

运行时使用底部的暂停、继续和 **“结束本轮”**。暂停会释放按键，继续后返回游戏；暂停期间的时间不计入本轮运行时限。

辅助功能权限可用时，任务运行期间可用 **F9** 暂停或继续。系统占用该键时可尝试 **Fn + F9**；快捷键不可用则使用面板按钮。任务结束后键盘监听关闭。F9 的协议已做离线验证，游戏现场效果仍需短轮次测试。

关闭面板会先请求停止，等待任务子进程退出后关闭。尚未核对的消费保留到下次启动；停止或重启不会自动重复领取。等待停止完成后，再手动改队伍、游戏窗口或显示设置。

“运行记录”显示每轮结果及核对后的波片、溶剂和储备消耗。出现“待核对”时先处理异常，不要连续再次开刷。

## 7. 异常与恢复

**不要删除账本或待核对文件来恢复运行，也不要在结算不明确时再次点击领取。** 这些记录用于区分已经消费、尚未消费和无法确认的情况。

声骸领奖中断且游戏仍停在原结算页时：

1. 保留结算页面，进入面板 **“异常与恢复”**。
2. 点击 **“读取当前结算”**。程序只读取并保存两帧当前画面，不点击游戏。
3. 点击 **“核对已领取结果”**。只有消费前记录、两帧新鲜且一致的结果、账本基线及预算都匹配时，才确认消费；已记账的同一次领取不会重复计入。
4. 核对成功后使用 **“返回并检查血量”**，再决定是否开始下一轮。消费核对成功不等于整轮任务全部完成。

以下情况会继续保留待核对状态：缺少原始记录、两帧读数不一致、画面已离开结算、旧版记录缺少账本基线，以及当前尚不支持自动核对的材料领奖或补给异常。此时点击 **“导出诊断包”** 并反馈给维护者，不要手工填写波片数字或清除记录。

导出的诊断包只包含筛选、脱敏后的状态和资源计数，不包含原始游戏截图、整份日志或账号配置。声骸会堆叠，背包标题数量变化不等于本轮奖励总件数，程序不会据此宣称逐件验收成功。

## 8. 屏幕、窗口与缩放

面板最小窗口为 **920 × 600 逻辑像素**，系统可用区域还需容纳窗口边框。窄窗口改为单列，页面内容纵向滚动，底部运行按钮保持可见。正常窗口启动或换屏时会调整到屏幕可用区域；最大化和全屏状态保留。

离屏布局检查覆盖 920 × 600、1000 × 640、1220 × 680、1220 × 900、1600 × 900，以及 1×、1.5×、2×缩放。这是软件布局检查，不代表这些显示设备都已运行游戏。

游戏画面单独适配：配置支持 **16:9、16:10、43:18**，最低采集 **1280 × 720**，区分 Retina 物理像素和鼠标逻辑坐标。已有保存帧或实测记录包括 1920 × 1080、3024 × 1898、3440 × 1440。启动时发现不支持的尺寸或比例，会显示原因。

首次试跑固定游戏窗口和显示器。需要移动窗口、跨屏、改分辨率或切换全屏时，先结束本轮，调整后重新检查队伍。运行中检测到位置、尺寸、显示器或缩放变化时，会停止新输入、释放已按下的按键，并保留账本和待核对记录。真实多显示器切换尚未完成实机验收。

## 9. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 找不到 Python 或提示版本不符 | 安装 Python 3.13，重新打开终端再运行安装入口；不要改用系统 Python |
| 缺少 `swiftc` | 完成 `xcode-select --install`，用 `xcrun --find swiftc` 检查 |
| 依赖下载中断 | 保留终端错误，网络恢复后重新运行安装入口；不要自行改用未锁定的依赖版本 |
| “发布包文件已变化”或文件缺失 | 保留旧目录中的用户记录，重新下载并完整解压原附件；不要继续混用两个版本的源码 |
| 已有 `.venv` 不是 Python 3.13 | 安装器不会覆盖；保留旧目录，在新的解压目录安装，再按下节处理已有记录 |
| 配套框架缺失或模块无法导入 | 检查 `ok-wuthering-waves` 与 `ok-script` 仍为同级完整目录，运行“环境诊断” |
| 无法采集、黑画面或无法输入 | 检查启动终端的屏幕录制与辅助功能权限，完全退出并重开终端，确保原生游戏已打开且未最小化 |
| 队伍、等级或索拉等级无法确认 | 返回大世界，关闭遮挡菜单，恢复生命值后重新检查；不要沿用旧报告 |
| 资源记录异常或有待核对消费 | 使用“异常与恢复”读取与核对；不支持的情况导出诊断包 |
| 提示另一个控制器正在运行 | 先正常结束另一面板或任务，再重试；不要手动删除锁文件 |
| 运行中提示窗口变化 | 结束本轮，固定窗口与显示设置，再重新检查队伍 |
| F9 无效 | 使用面板暂停按钮；检查辅助功能权限及系统功能键设置 |

## 10. 升级与保留记录

**资源记录属于用户安装，升级不能重置消费历史。** 本版没有一键迁移工具。重新运行当前版本的安装器可以修复依赖，不会清空账号配置或账本。

升级或重新解压前：

1. 结束任务并关闭面板。有待核对消费时先按恢复步骤处理；无法核对时保留现场记录。
2. 备份并保留整个旧解压目录，尤其是项目内的 `configs/` 和 `logs/`：账本、备份、安装标记、检查点和待核对证据需要一起保留。不要把这些文件发到公开仓库。
3. 将新版本完整解压到新目录，按该版本说明安装。不要覆盖混合两版源码，也不要复制旧虚拟环境。
4. 使用新版本提供的迁移说明；没有兼容迁移说明时，已有账号继续使用旧目录，联系维护者核对迁移范围。**不要在新目录勾选首次使用来替代迁移，也不要只复制一个账本文件后开刷。**

如果只是重新下载同一个版本，也同样保留完整旧记录，不通过删目录、删账本或重新初始化恢复额度。

## 11. 验证范围与反馈

0.1.0-beta.1 已在全新 Python 3.13 依赖环境中通过 **620 项隔离回归**；macOS 后端与启动错误模块 **49 项通过**，Swift 类型检查通过。固定依赖安装及 `pip check` 通过。这些验证不发送真实游戏输入，不等于完整游戏流程的实机验收。

另一台 Mac 和新账号、新面板的完整实战链、真实暂停/继续/关闭及中断恢复、多显示器切换、两套成型队伍连续运行，仍需内测验证。首次运行请有人看护，先做一轮小额度测试。

到 [GitHub Issues](https://github.com/Junsheng-He-Life/ok-wuthering-waves/issues) 反馈时，请附上：

- 包版本、Mac 芯片及 macOS 版本。
- 游戏窗口或全屏状态、分辨率与显示缩放。
- 任务、关卡、索拉等级、三人队伍及等级。
- 从哪一步开始、界面提示了什么、能否重复出现。
- 面板导出的诊断包；安装失败时附相关终端错误。

自行添加截图或终端输出前，请遮住 UID、账号信息和个人路径。不要上传整份 `configs/`、`logs/` 或虚拟环境。
