# 按角色培养：共用刷取项目

本地 GUI 的「按角色培养（自选项目）」增加共用多选：声骸、突破、武器/技能、周本、角色经验、武器经验、贝币。当前三人、指定一人、指定三人均使用同一组勾选；培养角色不会改变游戏出战队伍。默认只选声骸，领奖关闭。未选任何项目时拒绝启动，不回退成全部材料。

从「应用程序」打开「OK-WW 鸣潮助手」即可使用。已打开的旧窗口需关闭后重开。先选择角色与项目，再点「读取关卡 / 培养需求」。只选声骸时不扫描材料数量，也不会进入材料副本。材料项目从当前培养页读取持有/需求，满足或无法确认的项目不盲刷。突破任务不顺带运行声骸搜索。

声骸先从当前角色「声骸培养 / 合鸣图鉴」一行读取实际合鸣套装名，再在无音区的合鸣下拉筛选中选择同名套装，并确认筛选栏显示该名称。只从该筛选结果中选择重复观察到的关卡。每次入场重新读取角色方案并核对筛选；不使用旧的头像饱和度判断或通用奖励图标推断套装。无法核对时停止，不改刷其他无音区。当前尚无角色主词条/副词条毕业判定，也未增加推荐 Boss 或野外声骸路线。

所有角色与项目共用本次场数、奖励份数、波片、储备、溶剂额度及原持久账本。场数是整批上限，不是每角色分别计数；数量较小时，后面的目标可能未执行。关闭领奖时额度强制为零，材料走既有 practice 流程，声骸只搜索吸收。勾选领奖本身不改变此前的用户消费授权。

入口仍为 `scripts/ultrawide_trial.py`，新增 `--phase cultivation` / `cultivation-catalog`，配合必填 `--cultivation-kinds '声骸,突破'`。角色沿用 `--target` / `--targets`，留空时现场读取当前三人；不使用旧材料计划的缓存目标。新队列从头读取，不自动恢复上次任务；`cultivation-progress.json` 只记录本次结果，原领奖 pending 和控制锁继续拦截重复消费。

此次只做软件修改和离线模拟验证，未启动游戏控制器、未切培养目标、未战斗或消费。游戏暂停标记保留。实际推荐标记识别和新组合队列仍待实机验收，已有各关卡稳定性限制不变。

验证结果：138 项公开与相关定向离线检查通过，3 组非法 CLI 请求在游戏初始化前被拒绝，源码语法及 diff 空白检查通过。已检查预览布局，并通过「应用程序」入口重开 GUI，确认七项共用多选、默认只选声骸及不领奖状态可见。未点击读取或开始按钮。

后续实机前置核对暴露并修正了上述早期方案：心的白色头像不满足旧饱和度门槛，边界图像曾把玄幽东岳误报为推荐；该关卡没有开打。改为角色方案套装名及筛选栏双重核对后，现场确认心的「衔梦照世之心」对应沉心域、烬心域。下拉菜单需滚动找到后期套装，选中后筛选栏只显示套装名，不带「合鸣筛选/」前缀。原始截图和扫描日志保留在 `logs/cultivation-echo-scan/` 与 `logs/desktop-runs/`；至此消费仍为零。当前包含命名筛选修复和窗口内角色选择快捷键。
