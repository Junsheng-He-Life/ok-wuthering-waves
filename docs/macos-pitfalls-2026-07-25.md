# OK-WW macOS 实机踩坑记录

日期：2026-07-25
适用项目：

- `/Users/yourname/Documents/Games/ok-wuthering-waves`
- `/Users/yourname/Documents/Games/ok-script`

本文记录本轮实机调试中已经出现过的问题、根因、修复方向和必须保留的安全边界。

## 1. 最严重的误操作：未验证页面就点击固定坐标

### 现象

- 坐标落在了错误菜单或抽卡入口。
- 实际发生了抽卡，而不是执行预期的日常流程。
- 菜单与大世界之间反复打开、关闭。

### 根因

- 旧模板在新版界面产生假阳性。
- 在没有确认页面标题时直接使用固定坐标。
- 把“打开过菜单”误判为“当前仍在目标页面”。

### 规则

- 任何坐标点击前必须先确认当前页面标题或目标行。
- 页面验证失败时必须 fail closed：停止当前流程并保留截图，不能继续猜坐标。
- 涉及抽卡、商城、确认按钮等高风险区域时，禁止使用未验证的固定坐标。

## 2. F2 热键失效与菜单反复横跳

### 现象

- F2 没有打开索拉指南。
- 程序误以为仍在大世界，连续发送 Esc 或重复开书。
- 大世界和菜单之间来回切换。

### 根因

- macOS 游戏偶尔没有接收普通热键。
- 大世界识别模板位置有偏移。
- 旧流程没有在每次恢复动作后重新验证状态。

### 当前策略

1. 优先发送配置中的 `Guidebook Key`，当前为 `F2`。
2. 热键失败时，只允许一次原子的 `Option/Alt + 点击` 索拉指南世界图标。
3. 每次动作后重新 OCR 顶部页面标题。
4. 不允许无限 Esc；恢复动作必须有次数上限。

## 3. 索拉指南旧图标模板匹配到错误页面

### 现象

- `gray_book_quest` 旧模板匹配到新版“素材获取”的第三个图标。
- 程序以为进入了活跃行迹，实际停留在其他页面。
- 日常页面验证失败后又继续点击，形成循环。

### 修复原则

- 索拉指南页面使用顶部标题 OCR 验证。
- 标题使用精确白名单：
  - 索拉指南
  - 活跃行迹
  - 漂泊日志
  - 周期挑战
  - 素材获取
- 不再用宽泛文本匹配替代页面身份。

## 4. OCR 过宽导致地图地名被识别成索拉指南

### 现象

地图中的 `乘霄山` 等文字被宽泛正则误判为索拉指南标题。

### 规则

- 页面标题必须整行精确匹配。
- OCR 框只覆盖左上角标题区域。
- 地图、任务名和页面标题不能共用宽泛正则。

## 5. 日常“0/180”行与“前往”按钮不能使用固定纵坐标

### 现象

- 活跃行迹已经打开，但程序没有继续。
- 固定坐标点击到了错误日常任务行。

### 当前策略

- OCR 搜索严格格式 `N/180`。
- 使用识别框中心计算该行的纵坐标。
- 只点击同一行右侧的 `前往`。
- 行坐标超出安全区间时停止，不进行坐标动作。

## 6. “前往”不等于“未解锁”

### 现象

程序仅根据按钮文字或打开地图失败，就认为整个素材类别不可用。

### 正确认知

- `直接挑战`：当前可以确认入口可直接使用。
- `前往`：会进入地图或定位流程，本身不表示已解锁或未解锁。
- 真正的解锁判断必须在目标地图页面识别：
  - 可用快速旅行；
  - 灰色传送；
  - 移除标记；
  - 直接进入编队/挑战。

未知页面状态必须停止，不能自动切换到另一个素材。

## 7. 未解锁页面的 Esc 层级

实机确认的恢复路径：

1. 未解锁目标页面按一次 Esc，通常只退回完整地图。
2. 再按一次 Esc，才退回大世界。
3. 某些叠层可能需要第三次，但必须限制最大尝试次数。

当前安全上限为 3 次。每次 Esc 后都要重新验证页面，不能盲发。

## 8. “优先直接挑战”可能刷错素材

### 现象

动态字典把同一大类中的所有地区入口放在一起，再全局优先 `直接挑战`。

### 实机反例

凝素领域中，梦州和黎那汐塔都有“迅刀”行，但掉落材料系列与图标不同。当前培养
目标头像标在梦州的 `陨翼云渊` 关卡行；`陨翼云渊` 是关卡名，不是材料名。不能
因为黎那汐塔可以直接挑战就切过去。

### 正确顺序

1. 当前培养目标；
2. `UP` 大类；
3. 培养目标头像或奖励素材图标指纹；
4. 同素材地区入口；
5. 入口状态；
6. 在完全同素材的集合内优先 `直接挑战`。

没有同素材替代时应停止或跳过，不能刷其他材料。

## 9. Daily 为什么总是进入无音清剿

当前 `configs/DailyTask.json` 中：

```json
"Which to Farm": "Tacet Suppression"
```

Daily 会直接调用 `TacetTask.farm_tacet()`，随后打开 `wuyin`。这不是动态素材字典
自动判断的结果，而是配置固定选择。

当前动态字典只扫描无音清剿内部地区，不能自动判断培养目标需要模拟领域、凝素领域、
讨伐强敌或战歌重奏。

## 10. 右侧列表的滚动方式

### 现象

鼠标滚轮位于奖励图标行时，会横向切换奖励展示，而不是纵向滚动整个地区列表。

### 规则

- 纵向扫描应抓住最右侧滚动条拖动。
- 当前滚动条横坐标约为相对位置 `x=0.973`。
- 不要在奖励图标区域发送滚轮并假设页面已经纵向移动。
- 每次拖动后应通过地区标题或首尾副本名确认实际滚动结果。

## 11. macOS 普通模拟点击可能只移动鼠标

### 现象

通用电脑控制可以移动光标，但《鸣潮》不接收点击和滚动。

### 当前可用方式

- 使用 OK-WW 已校准的 macOS Quartz 输入后端。
- 需要时使用原子的 `modified-click`，在一次事件中完成
  `Option/Alt + 鼠标点击`。
- 不要把按下修饰键和点击拆成容易失配的独立流程。

## 12. Retina 坐标单位混用

必须区分：

- ScreenCaptureKit/OpenCV：帧像素；
- macOS 窗口几何：point；
- Quartz 鼠标事件：全局 point；
- OK-WW 任务层：相对坐标。

不能把 `1920 × 1080` 的帧坐标直接当成所有显示模式下的全局点。换算应使用当前
窗口尺寸与实际捕获帧尺寸。

## 13. 窗口偶尔找不到

### 曾出现的原因

- 首帧尚未到达，短暂显示 `0x0`。
- 多线程同时运行 ScreenCaptureKit 窗口枚举并超时。
- 旧进程或孤儿 helper 占用捕获链路。
- 代码修改后旧 OK-WW 进程仍在运行，没有加载新代码。

### 处理顺序

1. 确认《鸣潮》已启动且窗口可见。
2. 等待日志出现 `capturing frame (1920, 1080)`。
3. 检查是否存在重复的 OK-WW/Python/helper 进程。
4. 关闭旧 OK-WW 后重新启动；Python 代码没有热重载。
5. 只清理确认属于旧实例的进程，避免宽泛 kill。

## 14. macOS 权限授权后必须重启相关进程

需要：

- 屏幕与系统音频录制；
- 辅助功能。

用户在系统设置中开启权限后，原有 ChatGPT、终端、OK-WW 或 helper 进程可能仍然
持有旧的 TCC 状态。应完整退出并重新启动被授权的应用或启动链路。

权限提示不能被当成任务页面，也不能在权限未生效时继续发送坐标。

## 15. 自动战斗与无坐标鼠标事件

自动战斗会调用无坐标的 `click()` 或 `mouse_down()`。旧实现可能使用无效的
`(-1, -1)`，导致普通攻击没有落到游戏。

当前 macOS 后端的处理顺序：

1. 优先使用当前 Quartz 光标位置；
2. 若不可用，使用游戏窗口中心；
3. 鼠标抬起保留最后一次有效位置。

自动战斗是否完整可用仍需要按角色、技能和战斗场景继续实机验证，不能仅凭“按了一次
普通攻击”就判定全部流程通过。

## 16. 当前安全边界

- OK-WW 输入只能在《鸣潮》位于前台时发送。
- 页面身份未知时停止。
- 不在未验证页面点击确认、抽卡、商城或奖励坐标。
- 不因为任务难以恢复就无限发送 Esc。
- 不因为某个入口可直接挑战就切换到其他材料。
- 当前工作区含有未提交修改，后续改动应避免覆盖或回滚用户现有内容。
